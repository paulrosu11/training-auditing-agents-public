# Security Policy

## Private vulnerability reports

Please use GitHub's
[private vulnerability reporting](https://github.com/paulrosu11/training-auditing-agents-public/security/advisories/new)
for a suspected vulnerability, exposed credential, privacy issue, or unsafe
release artifact. Include the minimum information maintainers need to locate
and reproduce the issue safely. Do not include live credentials.

## Dataset takedown and correction requests

Send privacy, safety, attribution, correction, and takedown requests through
the same private vulnerability reporting channel. Do not reproduce sensitive
conversation text, personal data, credentials, or exploit details in a public
issue. A release-local record identifier and a non-sensitive description are
enough to start a private investigation.

If GitHub's private channel is unavailable, open a public issue containing
only a request for a private maintainer contact route. Do not include the
sensitive material itself.

For handling limitations and the WildChat-derived data policy, also see
[DATASET_CARD.md](DATASET_CARD.md) and
[THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).
